The tile's aria-label keeps the full label.
   Fit (PinnedStrip.tsx `TileModelLabel`): measured on the device in its own font, 11 px, then 10 px, then 9 px with -0.02em letter spacing, then an ellipsis. Line height is fixed so the strip height (105 px) never changes. Measured in Chrome on Windows: every Opus/Sonnet/Codex label up to "Sonnet 5.5 · Max" and "GPT-6-Astra · Max" fits at 72 px; "Muse Spark 1.3 · X" only fits at 9 px with the tight spacing. Only a model the provider does not list (raw id such as `opencode/muse-spark-1.3-contributor-free · X`) still ends in an ellipsis.
2. steer_task text that already starts "Update from <name>:" (case-insensitive) is not prefixed again (PersonalTaskService.ts `steerText`). Test in PersonalTaskService.test.ts.
3. "Waiting on <bot>" status. A thread whose task is unfinished (parked on a child, `waiting_for_agent`, or still `running` after its turn ended, i.e. waiting on background work) and has no live turn shows "Waiting on Planner", "Waiting on Planner and Developer", "Waiting on 3 bots" or "Waiting on a task" (no open child) in the Bots list row and the chat header, with a hollow ring instead of the live dot. Same `waitingLabelsByThread` as before, now also taking `running` tasks and reworded from "Waiting for" to "Waiting on" (delegation cards use the same text). Live update: it reads the task feed both screens already subscribe to, no new polling. The header also shrinks the provider name ("Cla…") before the status so a long status is never cut. Known trade-off: for a moment after a chat turn ends and before the task feed marks it completed, the row can read "Waiting on a task".
4. Answer, not a change: a running task chat shows no reasoning or tool steps by design. conversationModel.ts drops `reasoning` messages always ("a bot chat shows what the bot said, not how it got there") and drops every tool step unless Settings > Chat > "Show tool steps" is on (default off). Sonnet 5.5 puts its progress notes in thinking summaries (stored as `reasoning` messages) and speaks little between tool calls, so a Sonnet chat looks empty while an Opus chat, which narrates in text, does not. Option offered to Harout: a live one-line "latest progress" under the Working indicator from the newest reasoning summary. Not built (product decision).
