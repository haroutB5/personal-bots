# Team leads manage the bots on their team (1.55.0)

2026-09-29, Backend (CTO task d55e7c91). Branch feat/lead-manage-bots (worktree C:/Claude/AI/_wt/hbots-155), on 1.54.0 (88e920bf14, release 9a5f89ce0f0e, live since 15:07). Harout: "CFO is saying he can't create bots... add to any bot that is a team lead, to be able to add and remove and edit bots to their team."

## What changed

- **Three new bots tools** (apps/server/src/mcp/toolkits/bots/tools.ts, handlers.ts): `create_bot`, `update_bot`, `remove_bot`. They are listed for every bot with the bots capability but only a bot that is a team lead _at the moment of the call_ is served: the lead flag is re-read from the database on every call.
- **One permission function**: `authorizeLeadBotAction` in `apps/server/src/personal/leadBots/leadBotPolicy.ts`. Every rule is in it and the service acts only on its `allowed` verdict (`PersonalLeadBotService.authorize`, leadBots/PersonalLeadBotService.ts, reads the facts fresh and calls it once per action). Rules:
  1. caller must exist and be a lead now (`not_a_lead`, `caller_gone`);
  2. a call that names `team`, `lead` or `pinned` is refused, not ignored (`forbidden_field`; the tool schema carries the three fields only so they can be refused);
  3. a Fable or Mythos model is refused unless it is the model the bot already has (`forbidden_model`, `isLeadForbiddenModel`);
  4. create: the new bot goes on the caller's own team as a non-lead, unpinned member; at most `LEAD_BOT_CREATES_PER_DAY` = 5 per rolling 24 h (`rate_limit`, counted from the audit table);
  5. update/remove: the target must be a live bot on the caller's own team (case-insensitive, as the app compares), not the caller (`self`), not a lead (`other_lead`), not on another team (`other_team`, which is also what keeps the seeded system bots out of reach unless they sit on the lead's team);
  6. remove: refused while the target has an unfinished task (`running_task`: running, queued or waiting) or a routine switched on (`active_routines`).
- **Fields**: create_bot `name` (required), `title`, `description`, `instructions`, `avatarShape`, `avatarColor`, `provider`, `model`, `effort`, `notificationsMute`, `memoryAutoSave`. update_bot the same plus `bot` (id or name; a name shared across teams resolves to the lead's own team first). remove_bot `bot`, `reason`. Limits: name/title 60, description 500, instructions 20 000; names unique among all live bots (delegation finds bots by name). Model and effort come only from the provider lists (`leadBotModel.ts`): enabled, installed, able to carry the persona; an omitted model on create is the seed choice (Opus 5.5 medium, or PERSONAL_SEED_MODEL), never the lead's own model.
- **remove_bot is a soft delete only** (`PersonalBotService.remove`): the row gets `deleted_at`, every list drops it, and its chats, memories, secrets, routines and history stay. It differs from the app's own Delete, which is `purgePersonalBot` (deletes chats, memory, routines, its secrets): the task said "keeping the bot's chats, like the UI delete", but the UI delete does not keep them. Restore: `UPDATE personal_bots SET deleted_at = NULL WHERE bot_id = '<id>'` (needs Harout's OK and a backup; there is no restore button). The audit table holds the bot id.
- **Visibility**: every action writes (a) a row in `personal_lead_bot_actions` (migration 087; audit and rate limit), (b) a log line `personal lead bot action` (refusals: `personal lead bot action refused` with the code), (c) an assistant-role system row in the lead's chat (new chat-notice kind `team-bot-change`, marker in contracts personalChatNotices.ts; the web renders it as the existing notice line, text as written) and (d) a notification to Harout via the new `PersonalPushService.notifyTeamBotChange`: title "CFO created bot 'Tax'", body "Sonnet 5.5 · H on Finance", opens /bots/team, from the lead's avatar; always sent (no preference, the lead's own mute does not silence it). (c) and (d) are best effort: they can never undo the change.
- **Secrets**: the tools have no secret, connection or team fields; a created bot owns no secrets and gets no connection access. Text fields that look like a credential (PB_SECRET_ names, sk-/ghp_/xox/AKIA/JWT shapes, private keys) are refused (`looksLikeSecret`, a best-effort guard).
- **Group turns**: refused (the change is written in the lead's own chat).
- **Descriptions** tell the lead to ask Harout before remove_bot and before large instruction changes.
- **Web (not asked, needed)**: a card for a bot this device has never listed read "Deleted bot" (seen in the throwaway run: create + delegate in one turn). `unknownTaskBotsKey` (useRefreshBotsForTaskThreads.ts) now refetches the bots list when a task names an unlisted bot; ConversationScreen uses the hook too.
- **Task cards (CTO's addition)**: the card's second line is the bot's short model label ("Sonnet 5.5 · H", `taskCardBotLine` in botSummaries.ts, same `botModelShortLabel` as the list and pinned tiles); the provider name is only the fallback when no model is known. DelegationCard is the only card with that line (task page and group cards never showed a provider).
