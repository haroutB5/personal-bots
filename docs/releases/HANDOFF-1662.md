# HANDOFF 1.66.2: the memory service split (Astra #9)

A refactor release: `PersonalMemoryService.ts` (2149 lines) is cut into smaller modules with the text of every function unchanged, plus four small pure policy modules with their own tests. No behaviour change, no migration, no new setting, no change to any tool output or kill switch. `PERSONAL_TASKS_CONCURRENCY` is still 5. Branch `chore/hbots-relsafety`, merged to `personal-bots/main` by fast-forward. Rollback target: 1.66.1 (`ba82972d7c0d`), binary only.

## What moved where (`apps/server/src/personal/memory/`)

The 1.66.0 pattern (HANDOFF-1660, part B): the service file keeps the public interface, the layer and the glue; `make` was cut statement by statement into factories that take the parts already built. Everything the old file exported is still exported from it (re-exports), so no import elsewhere changed.

Only the four policy extractions touched logic (each a pure function lifted out of its call site): the replace refusal (`replaceRefusal`), the Undo route (`undoRoute`), the turn origin and web-tool detection (`originOfMessage`, `usedWebTool`, `isOwnerMessageId`), the carried apps (`carryActiveApps`), the resend decision (`sessionHoldsRules`, `preferenceSend`; the compaction check still runs only when the other conditions hold) and the trace clearing rule (`tracePruneDue`). The shared mutable state that used to be `let` and `Map` variables inside `make` is now one `state` object in `memoryCore.ts`. The same cleanup in `taskCore` and `browserCore` was left out (optional in the brief, not small).

## What QA should focus on

Memory is on the risky list, so a focused check of the unchanged behaviour, in dark mode only: a chat turn carries the right rules block (global rules, the chat's app rules, the "other apps" index line), a second turn in the same chat carries the one-line reminder, a new app rule saved mid-chat arrives alone, the Memory screen lists and edits (save, forget, restore, Undo on a "Saved a rule" line), `search_memory` and `save_memory` through a bot with the fake CLI, and the "Context used" panel of a turn.
