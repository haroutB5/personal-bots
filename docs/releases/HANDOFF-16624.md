# HANDOFF 1.66.24

## What changed

1.66.24 is a hygiene batch on top of 1.66.23. Three focused fixes, no user-facing feature change except the glide's robustness:

- **The re-pin glide can no longer move backward** (`apps/web/src/features/personal/MessageList.tsx`, +19/-2): a downward glide frame now writes `Math.max(next, scroller.scrollTop)`, so a pinned write that overtakes the glide (QA saw the `items`-effect pin land inside the 120 ms window and pull the transcript back ~12 px on 2 of 16 wraps) stays the last word and the glide still lands exactly at the bottom through `landPinTween`. Chosen over cancelling the tween on that write because the cancel variant would also skip the end re-assert for a grown list and would close only one writer. The engagement contract is unchanged (composer-driven, pinned only, kill switch, reduced motion, the same cancellations and scroll-event guards). 4 new tests; 3 of them fail on 1.66.23's code.
- **The interrupted provider lookup no longer logs an error-looking line** (`apps/server/src/provider/makeManagedServerProvider.ts`, +27): the 1.66.22 rollback trigger. Root cause, traced: the shared cached maintenance resolution (`makeCachedProviderMaintenanceResolution`, 1-hour TTL) stores the interrupted run's exit in its `onExit` finalizer when a demand refresh interrupts the spawn mid-resolve under load; the replacement enrichment generation then reads that stored exit as an ordinary failure and `Effect.ignoreCause({ log: true })` renders it as `InterruptError: All fibers interrupted without error` at INFO. Interruptions bypass `Cause` handlers in effect 4.0.0-rc.115, which is why the resolve-site `catchTags` never saw it. Fix: a local `ignoreCauseWithoutInterruptNoise` used at the three `ignoreCause({ log: true })` sites in the file; an interrupts-only cause is swallowed silently, genuine failures and defects log exactly as before. Reproduction test fails before the fix, passes after; a second test pins that a real enrichment failure still logs.
- **The five stale provider tests are green** (test files only): `ProviderRegistry.test.ts` expected-list gained `deepseek`, and the four Claude reset-credit tests in `ProviderInstanceRegistryLive.test.ts` now use a Windows-valid fixture (a `claude.cmd` shim beside the npm package `cli.js`, mirroring a real install) instead of a shebang script that cannot spawn on Windows; POSIX keeps the identical script, `HostProcessPlatform` is pinned to `linux` only on darwin, assertions unchanged.
